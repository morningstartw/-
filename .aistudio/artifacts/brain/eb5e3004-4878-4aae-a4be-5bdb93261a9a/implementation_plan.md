# AI 智慧冰箱與食譜助理 — 全方位功能升級實施計畫

本升級計畫旨在將現有的食材盤點與單道食譜工具，擴展為完整的家庭廚房與健康管理中心。系統將整合「週菜單規劃與缺料採買清單」、「即期品與巨量營養素儀表板」以及「一湯兩菜 / 兩菜一湯的多道套餐組合生成」，實現全週期、零浪費的智慧飲食生活。

---

## 使用者確認事項與關鍵決策 (User Review & Critical Decisions)

> [!IMPORTANT]
> 根據第一階段需求訪談，以下為確認之核心方向與架構配置：

- **確認項目 1：週菜單排程與缺料採買清單 (Weekly Planner & Smart Grocery List)**
  - 支援週一至週日的餐期（午餐、晚餐）排程規劃。
  - 當安排的菜色所需食材超過現有冰箱庫存時，系統自動將差額食材彙整為「缺料採買清單 (Missing Grocery Checklist)」，支援勾選採購與一鍵入庫。
- **確認項目 2：即期食材防浪費與巨量營養素儀表板 (Expiry Alerts & Macronutrient Dashboard)**
  - 冰箱首頁新增即期食材視覺警示卡，優先引導消耗 3 天內到期品。
  - 提供每日/每週巨量營養素統計（熱量 kcal、蛋白質、碳水化合物、脂肪），直觀掌握健康飲食狀態。
- **確認項目 3：維持極簡照片盤點體驗 (Keep Photo Inventory Streamlined)**
  - 維持現有的「拍照/上傳 ➔ AI 視覺多模態辨識 ➔ 數量 Stepper 快速微調 ➔ 一鍵加入冰箱」的高流暢度極簡設計，不增加繁雜的圖片方框遮罩操作。
- **確認項目 4：多道菜套餐組合推薦 (Multi-dish Combo Generator)**
  - AI 大廚升級支援「套餐模式」：一次生成「一湯一菜」或「兩菜一湯」均衡組合。
  - 同時提供單一菜色與套餐組合之切換，兼顧快速單人食與家庭豐盛用餐情境。

## 1. 產品概述與核心理念 (Overview & Core Concept)

- **核心價值**：
  從「單次解決眼前剩菜」晉升為「持續性的家庭飲食管理」。使用者不僅知道冰箱有什麼、能煮什麼，還能預先規劃未來幾天的飲食平衡，在採買前清楚了解缺少哪些調料或食材，避免重複採購。
- **目標受眾**：
  1. **自煮上班族與家庭主廚**：需要有系統地安排一週餐點，不想每天下班重複為「今天吃什麼」煩惱。
  2. **健身與飲食控制者**：嚴格監控蛋白質與熱量攝取，需清楚了解整週的營養素分佈。
  3. **惜食環保實踐者**：杜絕冰箱深處發霉過期，落實零剩食零浪費原則。

## 2. 使用者體驗與介面規格 (User Experience & Visual Design)

### 主要使用者流程 (Key User Flows)

1. **週菜單規劃流程**：
   - 使用者切換至「週菜單 (Weekly Plan)」分頁。
   - 瀏覽週一至週日的午餐與晚餐卡片，可直接從推薦食譜清單拖曳或加入菜色。
   - 系統即時比對全週預定消耗食材與現有庫存：
     - 若庫存充足，標示「庫存就緒」。
     - 若食材不足，自動產出「需補充採買清單」，點擊即可將缺額食材打勾採買。
2. **多道菜套餐料理流程**：
   - 在食譜條件前導頁中，模式切換為「一湯兩菜 / 套餐組合」。
   - AI 同時生成包含主菜（如黑椒蒜香雞）、副菜（如清炒時蔬）、湯品（如番茄豆腐蛋花湯）的完整菜單。
   - 提供「烹飪排程建議」（例如：先煮湯、微波備料、最後熱鍋快炒），省時高效。
   - 點擊「全套煮完！」一鍵扣除全套菜色所用食材，同樣具備 5 秒 Undo 復原機制。
3. **健康營養與即期品儀表板**：
   - 冰箱頂部展開「庫存健康指數」，包含「即期食材消耗進度條」與「近一週熱量/蛋白質攝取曲線」。

### 視覺語言與樣式規範 (Visual Identity & Theme)

- **設計調性**：自然清新、現代北歐有機廚房風格，以鼠尾草綠 (Sage/Emerald)、暖石灰 (Warm Slate) 與柔和琥珀橘 (Amber) 為主色調。
- **排版層級**：
  - 標題：強調清晰對比，避免過度花俏的裝飾。
  - 數值與計時器：採用等寬數字 (`tabular-nums` / `font-mono`)，確保營養數據與計時器垂直對齊整齊。
  - 零藥丸標籤約束：靜態詮釋資料（例如日期、熱量、難度）採用自然點分隔符號 (`·`) 排版，非點擊控制項不濫用圓角藥丸外框。
- **動態回饋**：
  - 採買清單勾選完成劃線微動效。
  - 烹飪計時器倒數進度環。
  - 5 秒防呆復原 Toast 全局浮動提示。

## 3. 關鍵架構決策與權衡 (Key Product Decisions & Trade-Offs)

### 決策 1：採買清單與冰箱庫存的雙向同步機制
- **選定方案**：
  將「缺料採買清單」與「冰箱庫存」建立雙向關聯。當使用者在採買清單勾選已購買食材後，提供「一鍵將已購物品入庫至冰箱」按鈕，並自動帶入預設有效期限（5 天）。
- **理由**：
  消除紙本或另外開備忘錄記帳的斷層，實現「計劃 ➔ 採買 ➔ 入庫 ➔ 烹飪 ➔ 扣除」的閉環。

### 決策 2：套餐推薦模式的 Prompt 最佳化
- **選定方案**：
  在後端 `/api/generate-recipes` 擴充 `mode: "combo" | "single"` 參數。當 `mode === "combo"` 時，提示詞引導 Gemini 3.8 Flash 根據冰箱食材分配出兼具主菜、副菜與湯品的結構化 JSON 套餐，並計算整套料理的總耗時與並行料理排程順序。
- **理由**：
  比生成 3 道獨立無關的菜更具實用性，避免三道菜都需要同一個鍋子大火快炒的衝突。

```
         │                  │                     │

│ POST /api/swap-recipe     │ POST /api/recognize-ingredients │

```

### 資料模型擴充 (Data Models)

1. **WeeklyMealSlot**：
   - `id`: string
   - `dayOfWeek`: 'Monday' ~ 'Sunday'
   - `mealType`: 'lunch' | 'dinner'
   - `recipe`: Recipe | RecipeCombo | null
   - `isCooked`: boolean

2. **ShoppingItem**：
   - `id`: string
   - `name`: string
   - `amount`: number
   - `unit`: string
   - `category`: IngredientCategory
   - `isChecked`: boolean
   - `source`: 'auto_generated' | 'manual'
   - `relatedRecipeTitle`?: string

3. **RecipeCombo**：
   - `id`: string
   - `comboTitle`: string (例：高蛋白元氣套餐：黑椒雞胸 + 清炒花椰菜 + 番茄豆腐湯)
   - `dishes`: Recipe[]
   - `totalCookingTimeMinutes`: number
   - `combinedNutrition`: NutritionInfo
   - `cookingSequenceTips`: string (並行烹飪順序指示)

## 5. 實施步驟概覽 (Execution Phases)

1. **步驟一：擴充資料模型與後端套餐生成端點**
   - 在 `src/types.ts` 新增週菜單、採買清單與套餐類型。
   - 在 `server.ts` 擴充 `/api/generate-recipes` 支援套餐組合（Multi-dish Combo）生成。
2. **步驟二：建立健康儀表板與即期品防浪費視圖**
   - 在冰箱庫存頁頂部整合「即期食材消耗進度」與「巨量營養素統計卡」。
3. **步驟三：建立週菜單規劃器與缺料採購清單組件**
   - 新增 `WeeklyPlanner.tsx`：直覺視覺化排程，支援排入套餐或單菜。
   - 新增 `ShoppingListModal.tsx`：自動計算全週缺料，一鍵採買勾選入庫。
4. **步驟四：升級食譜與套餐互動詳情頁**
   - 支援並行烹飪步驟檢視、全套食材一鍵扣除與 5 秒復原功能。
5. **步驟五：整體編譯、型別校驗與端對端驗證**
   - 確保所有按鈕與流程具備完整事件處理器，無死點或靜態假元件。
